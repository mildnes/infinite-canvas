# 画布图片结果持久化

## 必须保持

1. **任务详情不是唯一结果目录。** 成功的画布图片任务在完成 CAS 同一事务写入 `canvas_image_task_results`；任务详情 10 分钟清理前先归档既有成功行。事务任一步失败均不丢原任务。
2. **只存稳定原图与最少元数据。** 结果索引不存请求、响应、提示词、base64、blob 或上游临时 URL；保留原图 storageKey、URL、原始尺寸、类型、字节及原任务／画板／节点绑定。预览永远不能替代原图结果。
3. **账号与任务身份不可放宽。** 单查／批查仅当前账号回退索引；保存时必须同时匹配 task id、source=canvas、source id 和 node id。不按提示词、时间接近、相邻节点或最新一张图猜结果。
4. **恢复不是再生成。** 查询失败节点重新打开仅查询原任务；归档命中仍沿用原响应格式，重复提交同 client task id 复用结果，不再次扣费。
5. **不能覆盖用户的新状态。** 已有 content 或 storageKey、用户停止、明确生成失败、新 task id 都原样保留；只补同一次运行的缺图 loading／查询错误／缺图 success。不要全局放宽 `acceptsTaskUpdate`。
6. **恢复结果必须真正落盘。** 初始脏检查基线在恢复前取保存项目；恢复后的 content/status 变化触发保存。恢复不改节点位置或尺寸，未知字段／大整数保留；CAS 冲突与账号切换保护不绕过。
7. **清理不影响调度。** 索引不进入活跃列表，不纳入 `HasFinishedGenerationTasks`；失败／取消任务仍按原期限清理，工作台来源策略不变。用户显式删除任务才删该用户索引，不删除媒体。

## 确定性守卫

- `repository/canvas_image_result_test.go`：清理后单查／批查仍可恢复、账号隔离、升级归档、索引失败事务回滚、停止不被迟到响应复活。
- `repository/canvas_image_result_media_test.go`：多张稳定原图保留，临时 URL／base64 不进入索引。
- `service/canvas_image_result_recovery_test.go`：真实保存入口恢复，同任务绑定限制、已有媒体和终态保护、布局与大整数保留。
- `router/canvas_image_result_recovery_test.go`：真实 HTTP 完成→清理→查询／批查→旧节点保存→回读、CAS 409、旧状态重放、重复创建不再生成、显式删除隔离。
- `web/src/lib/canvas-image-result-recovery.test.mjs`：从实际页面 AST 提取恢复／apply 函数，查询错误与 loading 恢复，非成功任务不当成功；保持几何与保存基线。

新增用例必须在旧实现上产生业务断言失败，不能用编译失败替代。不得把媒体 apply 函数替换为恒成功的测试桩来证明恢复正确。

## 边界

已在旧版本中被清掉且没有任何精确映射的历史任务，不能凭空恢复。可用原始审计日志、成功时 Agent 上下文和字节校验确证的结果，先备份再定点补索引／节点；不得批量按时间猜图。不在本功能中自动回收成功索引或原图，回收须另有引用安全规格。
