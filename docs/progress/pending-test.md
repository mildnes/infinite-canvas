# 待测试

- 调整音频截取范围后试听应立即暂停并回到新起点；视频节点失选后应立即停止播放。
- 在节点输入框等交互面板上按住空格或切换移动工具拖动时应平移画布，普通选择模式仍可正常输入和操作控件。
- WebDAV 自动同步 MP4 时，后端上传与浏览器直连生成的对象名均应以 `.mp4` 结尾；其他 MIME 的扩展名保持不变。
- Agent 输入框把光标放在行首、行中、行尾后点击画布节点，引用应插入当前光标位置；重复点击已选节点可再次插入且不留下失效引用。
- Agent 回复中的行内节点 ID 应显示实时节点摘要，标题、状态和缩略图随画布变化；点击可定位节点，节点删除后回退普通代码文本。
- 火山方舟渠道在本地和管理后台均可显式选择 `ark` 协议；标准 API 与 Agent Plan 可创建并轮询 Seedance 任务，正确读取 `content.video_url`，并将 `expired` 识别为失败。
- Ark Seedance 2.5 应支持最多 30 张图片、10 个视频、10 个音频，参考视频最大 200MB、单个及总时长 30 秒；本地图片可转 Base64，视频和音频必须使用公网 URL。
- 画布节点生成使用绝对 HTTP(S) 图片素材时不应重复下载并转 Base64；Blob、Data URL、IndexedDB 和其他本地素材仍应正常转换。
- 图片工作台、画布节点配置和 Agent 图片设置应统一显示低、中、高、极高、最高、自动六档；生成、重试和恢复后保留原选择。
- 通用图片接口应分别收到 `low`、`medium`、`high`、`xhigh`、`max`、`auto`；Gemini、智谱、Agnes、Grok2API/xAI 等固定枚举渠道应映射为合法最高档，`xhigh/max` 不得退回 `auto`。
- 首页通过 `/` 或 Skill 弹窗选择 builtin/admin/system/user Skill 后进入画布，首轮 Agent 请求应继续使用所选 Skill；旧项目没有 `skills` 字段时仍可打开。
- Agent 推理关闭时请求体保持原样；开启后验证 Chat、Responses、Gemini、MiMo 的推理参数，并确认 Grok2API/xAI 渠道、模型和路由不变。
- 视频节点进度条应支持点击和拖动定位且不拖动画布；媒体源替换后进度归零。含音轨视频可生成并连接 WAV 音频节点，无音轨时不得生成空节点。
- 音频截取范围不得短于 0.5 秒，试听到选定终点自动停止；本地、`server:`、WebDAV 和远程媒体均可处理，失败后不残留加载状态或错误连线。
- 自动同步关闭时保持现有行为；开启后图片、视频、音频和派生 WAV 只上传一次并保留云端元数据，同步失败时原始 URL、Blob、Base64 或本地键仍可用且只提示一次。
- 媒体恢复不应产生重复上传；仍被撤销/重做历史、其他画布、素材库、生成日志、Skill 或 Agent 会话引用的文件不得删除。redo 覆盖、历史超过 50 步、离开画布、账号切换及迟到同步时只清理真正无引用的文件。
- 配置 `grok2api` 或 `xai` 渠道后，画布用 grok-imagine-image / grok-imagine-video 系列模型生成图片、视频，确认路由、字段和轮询结果识别正常。
- 管理端/本地渠道协议下拉可选 `Grok2API`、`xAI`，保存后渠道协议字段正确落库。
- grok2api 渠道经 `/api/v1/tts` 调用 TTS，确认 `language` 缺省为 `en`；`/audio/speech` 保持 OpenAI 字段透传；音色列表可从 `/tts/voices` 拉取。
- 管理端 grok2api/xai 渠道“读取模型”：上游 `/models` 有结果时保留 LLM，并合并内置媒体目录；上游失败时回退内置文本+媒体目录。账号实际权限需人工核对。
- 渠道协议仍为 `openai` 但模型为 `grok-imagine-video-1.5` 时，创建视频不再 404，应映射到 `/videos/generations`。
- Grok/xAI 图片 prompt（含系统提示词）超过 8000 字符时，前端/后端应给出明确错误，不再透传上游 400。
- Grok 图生图多参考图应传 `images:[{url}]`，不再误映射为视频字段 `reference_images`；非法 `aspect_ratio`/`quality`/`size` 会被清洗。
- Grok 视频：`image` 与 `reference_images` 互斥；**首帧单图（含 video-1.5）可选 1080p**；**仅多参考图模式最高 720p**；视频 `21:9` 吸附为 `16:9`。
- Safari 打开画布视频应能播放；若节点 content 仍是 /api/proxy-image?url=视频地址，前端会解成直链。
- 本地生成/上传图片后点“上传至云存储”，图片应仍可显示（content 为 /api/files/.../content 或可用预览，不应变 X）。
- 更换 WebDAV/S3 地址后，旧 providerId 的云端图应仍能通过当前存储回源显示；上传至云存储后当前页不应立刻变 X（可先本地预览）。
- 打开画板：本机 IndexedDB 本地媒体应自动上传 WebDAV/S3 并回写 server:；已有 server: 直接显示；Grok 等 https 原链只显示不自动转存。
- 节点/工具栏「上传至云存储」「一键上云」可将本地未上云与 Grok https 主动转存为 /api/files/...；另一浏览器同账号应可见。
- 失效 blob 且无 server/原链时显示失效占位，不白屏；保存/同步 JSON 不含 blob:。
- Safari 打开 content 为 /api/files/.../content 的云端视频/音频应能正常播放（需支持 Range）。
- gpt-image-2 等仅返回 base64 的生图：所有画布生成、批量生成、重试与轮询完成路径会先写入 `server:` 或 `image:`；刷新浏览器后图片仍在。有对象存储时确认节点为 `server:`，无存储时至少有 `image:` 本地键。
- 打开画板恢复本地 Base64 媒体时，同一文件若同时存在于节点、Agent 历史图片或引用中，WebDAV/S3 只上传一份，所有引用回写同一个 `server:` 指针。
- 旧版本已丢失 content 但仍保留 `imageTaskId` 的成功图片，登录后打开画板应批量从云端任务记录取回结果并写入 `server:` 或 `image:`；任务记录不存在时维持失效占位，不扫描 WebDAV 目录猜测文件。
- Agent 对话框输入 @ 可弹出画布图片/视频/音频列表；插入芯片后发送，Agent 应识别对应节点引用。
- 画布选中图片/视频/音频时，Agent 输入框上方应显示附件缩略图并随本轮发送；输入 `@` 明确引用时以 `@` 引用为准，不叠加其他选中节点。选中 group 或图片批次时应展开其中可用媒体。
- 后台私有设置新增画布 Agent 扩展：可新增/启停/编辑 Skill，新增/启停 MCP 服务，读取工具列表；保存后 API Key 脱敏并可沿用。
- 画布 Agent 会话应自动加载启用 Skill 与 MCP 工具，模型可调用 `mcp__<服务>__<工具>` 工具，后端转发 JSON-RPC `tools/call` 并把真实结果回传模型继续执行。
- 用可生成视频的 MCP 工具走 Agent 生成视频并落回画布，确认工具参数传递、媒体 URL/文件结果能被模型识别，并通过 `create_media_node` 创建视频节点。
- 后台 MCP 分别配置 `Streamable HTTP` 和 `stdio`；HTTP 服务验证初始化/会话头，stdio 服务验证进程复用、异常重启和工具调用。
- Agent 输入 `/` 应能筛选并引用内置 Skill、后台 Skill；Skill 芯片只作用本轮，重试历史消息时仍能带回对应 Skill。
- 管理后台使用“从 GitHub 安装”输入仓库地址或 `SKILL.md` 地址，确认名称、描述、正文和来源信息正确保存，刷新后仍可启停并被 Agent 使用。
- 画板上传图片：云端 WebDAV/S3 异常时不应整页失败；应提示真实错误并回退本地保存，节点仍可上画布。
- 画板上传图片到 WebDAV/S3 成功后不应误报“云端存储失败”；节点应保留 `server:` 指针并使用本地 Blob 即时预览，刷新后不应再次上传同一文件。
- 登录用户首次进入且后台允许云端渠道时，应直接使用后台默认文本、图片、视频、音频模型；用户在配置页主动切换“本地直连”后，后续登录应保留该选择。
- Gemini 协议渠道应能调用原生文本、图片、视频和 TTS；MiniMax H3 官方协议应能创建、轮询视频任务。
- 图片渠道的 `apiMode=chat` 应通过 Chat Completions 生图并正确解析图片结果。
- 未登录使用个人 S3/R2 或 WebDAV 时，Base64 生图刷新后仍可恢复；WebDAV/S3 媒体读取应按 Range 按需分段，Safari 视频/音频可播放。
- 升级后首次启动：旧 `private.agent.skills` 应一次性迁移至系统 Skill；管理员在“Agent Skill”页可继续管理，MCP 服务仍在系统设置私有配置中可编辑，HTTP 和 stdio 均能读取工具列表。
- Agent 文本接口可在 Chat Completions 与 Responses 间切换；长会话应创建检查点压缩，并能按需查询画布节点和 Skill 附属文本文件。
- Agent 首页和画布输入框应仅显示具备图片能力的模型；选择结果按当前画布保存模型与渠道，文本 Agent 模型不变；同名模型按 `channelId` 区分，模型失效时回退后台当前默认，并遵守媒体自动生成开关。
- Grok2API/xAI 等图片任务完成后，画布应在快速轮询阶段约 1 秒内发现结果；多图批量生成应合并状态查询和画布更新，历史外链经 `/api/proxy-image` 显示时应流式返回且不改变各渠道生成协议。
- Seedance 2.5 在设置面板和 Agent 中应支持 `-1`、20、25、30 秒；其他 Seedance 型号仍限制在原有 15 秒范围。
- Agent 依次验证原生 Tool Calling、Structured JSON、Prompt JSON 降级；不完整 JSON、未知工具、参数类型错误和超过上限的工具批次必须整体拒绝，动态 MCP 工具也遵守同一校验。
- 显式使用 `/ Skill` 时只加载核心规则和所选 Skill；未选 Skill 时仍保留自动工作流与意图路由。连续插入 `@` 素材或 `/` Skill 不应产生额外空行。
- 对跨域、WebDAV/S3 或 Safari 视频地址执行首帧、尾帧和当前帧截取：直连失败时应通过媒体代理重试，成功后可生成图片节点。
- 渠道回归：OpenAI、Gemini、Grok2API/xAI、Metaso、KIE、APIMart、MiMo 均应保持当前请求路径、鉴权、模型目录和任务结果解析；`protocol=openai` 配合 Grok/xAI Base URL 仍按 Grok/xAI 媒体协议处理，KIE/APIMart 优先。
- Agent 媒体自动生成关闭时，应先创建配置完成的媒体节点并允许手动提交；开启时保持自动提交。
- 图片节点连线参考图与显式参考图均应传入，且顺序稳定；视频节点应支持预览、全屏、下载以及首帧、尾帧、当前帧截取为图片节点。
- 画布提示词弹窗编辑、参考内容预览/断开/重新选择、左侧组树展开收起、消息完整复制、视频复制粘贴删除快捷键均应正常。
- 旧成功图片记录若 `images` 为空但任务仍含 `image_url`、`url` 或 `storageKey`，打开图片工作台后应自动回填显示。
